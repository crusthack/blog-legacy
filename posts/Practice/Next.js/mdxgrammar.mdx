# Markdown과 MDX 문법

Markdown은 **읽고 쓰기 쉬운 일반 텍스트 문서 형식**이다. 문법 기호가 적용되지 않은 원문만 보더라도 문서의 구조와 의미를 쉽게 파악할 수 있도록 설계되었다.

MDX는 Markdown에 JSX를 결합한 형식이다. 일반적인 Markdown 문법을 그대로 사용하면서 React 컴포넌트를 문서 안에 배치하거나, Markdown 요소를 원하는 컴포넌트로 교체할 수 있다.

| 형식 | 주요 목적 |
| --- | --- |
| Markdown | 제목, 문단, 목록, 링크, 이미지, 코드 등 일반 문서 작성 |
| GFM | 표, 작업 목록, 취소선 등 GitHub 스타일 문법 확장 |
| MDX | Markdown 문서에서 JSX와 React 컴포넌트 사용 |

> Markdown은 출판 형식인 HTML을 완전히 대체하려는 언어가 아니다. 글을 읽고 쓰는 과정은 Markdown으로 단순하게 유지하고, Markdown으로 표현하기 어려운 부분만 HTML이나 MDX 컴포넌트로 보완하는 것이 기본 원칙이다.

## 1. 문단과 줄바꿈

하나 이상의 연속된 텍스트 줄은 하나의 문단으로 처리된다. 새로운 문단을 만들려면 중간에 빈 줄을 넣는다.

```md
첫 번째 문단입니다.
같은 문단에 이어지는 문장입니다.

두 번째 문단입니다.
```

일반적인 줄바꿈은 다음 방법 중 하나를 사용한다.

- 줄 끝에 공백을 두 칸 입력한다.
- 줄 끝에 역슬래시(`\`)를 입력한다.
- 명시적으로 `<br />`를 사용한다.

```md
첫 번째 줄의 끝에 공백 두 칸을 입력합니다.  
두 번째 줄입니다.

첫 번째 줄의 끝에 역슬래시를 입력합니다.\
두 번째 줄입니다.
```

## 2. 제목

제목은 줄 앞에 `#`을 붙여 작성한다. `#`의 개수에 따라 `<h1>`부터 `<h6>`까지 대응한다.

```md
# 제목 1
## 제목 2
### 제목 3
#### 제목 4
##### 제목 5
###### 제목 6
```

Markdown에는 밑줄을 이용한 Setext 방식도 있다.

```md
제목 1
======

제목 2
------
```

문서 구조를 명확하게 유지하려면 페이지 제목에는 `#`을 한 번만 사용하고, 하위 절에서 `##`, `###` 순서를 지키는 편이 좋다.

## 3. 텍스트 강조

```md
*기울임꼴*
_기울임꼴_

**굵게**
__굵게__

***굵은 기울임꼴***

~~취소선~~
```

렌더링 결과는 다음과 같다.

*기울임꼴*, **굵게**, ***굵은 기울임꼴***, ~~취소선~~

문법 기호 자체를 표시하려면 역슬래시로 이스케이프한다.

```md
\*별표를 문자 그대로 표시합니다.\*
```

## 4. 인용문

줄 앞에 `>`를 붙이면 인용문이 된다.

```md
> Markdown은 읽기 쉬운 일반 텍스트 형식을 지향합니다.
```

인용문은 여러 문단을 포함하거나 중첩할 수 있다.

```md
> 첫 번째 단계의 인용문입니다.
>
> > 두 번째 단계의 인용문입니다.
>
> 다시 첫 번째 단계입니다.
```

인용문 안에서도 제목, 목록, 코드 등의 Markdown 문법을 사용할 수 있다.

```md
> ### 인용문 안의 제목
>
> 1. 첫 번째 항목
> 2. 두 번째 항목
```

## 5. 목록

### 5.1 순서 없는 목록

`-`, `*`, `+`를 목록 기호로 사용할 수 있다.

```md
- 빨강
- 초록
- 파랑
```

들여쓰기를 사용하면 중첩 목록을 만들 수 있다.

```md
- 프런트엔드
  - React
  - Next.js
- 백엔드
  - Node.js
```

### 5.2 순서 있는 목록

숫자와 마침표를 사용한다.

```md
1. 프로젝트 생성
2. 의존성 설치
3. 개발 서버 실행
```

원문의 숫자가 모두 `1.`이어도 일반적으로 렌더링 결과에는 순서가 자동으로 부여된다.

```md
1. 첫 번째
1. 두 번째
1. 세 번째
```

문장이 의도치 않게 목록으로 해석되는 경우 마침표를 이스케이프한다.

```md
1986\. 좋은 시즌이었다.
```

### 5.3 여러 문단이 있는 목록

목록 항목 안에 문단, 인용문, 코드 블록을 넣으려면 하위 내용을 들여쓴다.

```md
1. 첫 번째 문단입니다.

   같은 목록 항목의 두 번째 문단입니다.

   > 목록 안의 인용문입니다.

2. 다음 항목입니다.
```

### 5.4 작업 목록

GFM을 사용하는 환경에서는 체크박스 형태의 작업 목록을 작성할 수 있다.

```md
- [x] Markdown 문법 확인
- [x] MDX 컴포넌트 연결
- [ ] 글 발행
```

- [x] Markdown 문법 확인
- [x] MDX 컴포넌트 연결
- [ ] 글 발행

## 6. 링크

### 6.1 인라인 링크

```md
[MDX 공식 문서](https://mdxjs.com/)
[제목이 있는 링크](https://mdxjs.com/ "MDX")
[소개 페이지](/about)
```

### 6.2 참조 링크

URL을 본문 밖에서 정의하면 긴 링크 때문에 문장이 흐트러지는 것을 막을 수 있다.

```md
자세한 내용은 [MDX 문서][mdx]와 [CommonMark 문서][commonmark]를 참고한다.

[mdx]: https://mdxjs.com/
[commonmark]: https://commonmark.org/
```

링크 이름은 대소문자를 구분하지 않는다. 링크 텍스트와 참조 이름이 같다면 빈 대괄호를 사용할 수도 있다.

```md
[Daring Fireball][]

[Daring Fireball]: https://daringfireball.net/
```

### 6.3 자동 링크

URL이나 이메일 주소를 꺾쇠괄호로 감싸면 자동 링크가 된다.

```md
<https://mdxjs.com/>
<address@example.com>
```

## 7. 이미지

이미지 문법은 링크 앞에 느낌표를 붙인 형태다.

```md
![대체 텍스트](/images/example.png)
![대체 텍스트](/images/example.png "이미지 제목")
```

참조 방식도 사용할 수 있다.

```md
![MDX 로고][mdx-logo]

[mdx-logo]: https://mdxjs.com/favicon.ico "MDX"
```

대체 텍스트는 이미지를 불러오지 못했을 때 표시되며, 스크린 리더가 이미지의 의미를 전달하는 데에도 사용된다. 장식용 이미지가 아니라면 내용을 설명하는 문구를 작성해야 한다.

이 블로그에서는 일반 Markdown 이미지 문법이 게시물의 `MdxImage` 컴포넌트로 연결된다. 웹 URL은 그대로 사용할 수 있고, 상대 경로는 현재 게시물의 이미지 디렉터리를 기준으로 처리된다.

```md
![외부 이미지](https://mdxjs.com/favicon.ico)
![게시물 이미지](diagram.png)
```

## 8. 인라인 코드와 코드 블록

### 8.1 인라인 코드

짧은 코드, 명령어, 파일명은 백틱 한 쌍으로 감싼다.

```md
개발 서버는 `npm run dev`로 실행한다.
```

백틱 자체를 코드로 표시하려면 바깥쪽 구분자에 백틱을 두 개 이상 사용한다.

```md
`` `code`처럼 작성한다. ``
```

### 8.2 코드 블록

코드 블록은 백틱 세 개로 감싼다. 시작 구분자 뒤에 언어를 지정하면 구문 강조가 적용된다.

````md
```ts
interface Post {
  title: string;
  content: string;
}
```
````

이 블로그에서는 코드 블록 제목도 지정할 수 있다.

````md
```ts title="lib/post/posts.ts"
export function getPostData(category: string, slug: string) {
  return { category, slug };
}
```
````

기존의 `언어:파일명` 형식도 지원되는 경우가 있지만, 의미가 명확한 `title="파일명"` 형식을 우선 사용하는 편이 좋다.

코드 블록 안에서는 Markdown 문법을 해석하지 않는다. 따라서 `<div>`, `*`, `&` 같은 문자를 코드 그대로 표시할 수 있다.

## 9. 수평선

한 줄에 하이픈, 별표, 밑줄을 세 개 이상 작성하면 수평선이 된다.

```md
---

***

___
```

`---`는 문서 맨 위에서 frontmatter 구분자로도 사용되므로 위치에 주의해야 한다.

## 10. 표

GFM 표는 파이프(`|`)와 하이픈(`-`)으로 작성한다.

```md
| 이름 | 문법 | HTML 요소 |
| :--- | :---: | ---: |
| 링크 | `[텍스트](URL)` | `<a>` |
| 강조 | `**텍스트**` | `<strong>` |
| 코드 | `` `code` `` | `<code>` |
```

콜론으로 열 정렬을 지정한다.

| 구분 | 의미 |
| --- | --- |
| `:---` | 왼쪽 정렬 |
| `:---:` | 가운데 정렬 |
| `---:` | 오른쪽 정렬 |

표의 각 줄에서 바깥쪽 파이프는 생략할 수 있지만, 일관성과 가독성을 위해 작성하는 편이 좋다.

## 11. 특수 문자와 이스케이프

Markdown 문법에 사용되는 문자를 그대로 표시하려면 앞에 `\`를 붙인다.

```md
\* 별표
\_ 밑줄
\# 해시
\[ 대괄호
\( 소괄호
\! 느낌표
\- 하이픈
\+ 더하기
\` 백틱
```

일반적으로 이스케이프할 수 있는 문자는 다음과 같다.

```text
\  `  *  _  { }  [ ]  ( )  #  +  -  .  !
```

HTML에서 특별한 의미를 가지는 `<`, `>`, `&`는 Markdown 렌더러가 문맥에 따라 처리한다. HTML 예제를 설명할 때는 인라인 코드나 코드 블록을 사용하면 안전하다.

```md
`<section>` 요소를 사용합니다.
```

## 12. HTML 함께 사용하기

Markdown으로 표현하기 어려운 구조는 HTML을 직접 작성할 수 있다.

```html
<table>
  <tbody>
    <tr>
      <td>Foo</td>
    </tr>
  </tbody>
</table>
```

블록 HTML은 앞뒤에 빈 줄을 두고, 시작 및 종료 태그를 불필요하게 들여쓰지 않는 것이 좋다.

```md
HTML 앞의 문단입니다.

<div className="notice">
  HTML 블록입니다.
</div>

HTML 뒤의 문단입니다.
```

MDX에서는 HTML 속성 대신 JSX 규칙을 따라야 한다.

| HTML | JSX/MDX |
| --- | --- |
| `class` | `className` |
| `for` | `htmlFor` |
| `tabindex` | `tabIndex` |
| `<br>` | `<br />` |
| `style="color: red"` | `style={{ color: 'red' }}` |

> 블록 HTML 내부에서 Markdown 문법이 항상 처리된다고 가정하면 안 된다. HTML이나 JSX 블록 안에서는 필요한 구조를 HTML/JSX로 명시하거나 별도 컴포넌트로 분리하는 편이 안전하다.

## 13. MDX란 무엇인가

MDX 파일에서는 Markdown과 JSX를 한 문서에서 사용할 수 있다.

```mdx
# 사용자 정보

일반적인 **Markdown 문단**입니다.

<UserCard name="CrustHack" />
```

MDX의 핵심 사용 방식은 두 가지다.

1. Markdown 문서 안에 JSX 컴포넌트를 직접 배치한다.
2. Markdown이 생성하는 기본 HTML 요소를 사용자 컴포넌트로 교체한다.

## 14. Markdown 요소를 컴포넌트로 교체하기

Markdown의 링크는 기본적으로 `<a>`로 변환된다.

```md
[MDX](https://mdxjs.com/ "MDX")
```

일반적인 JSX 결과는 다음 구조와 같다.

```jsx
<p>
  <a href="https://mdxjs.com/" title="MDX">MDX</a>
</p>
```

MDX 렌더러에 `components` 객체를 전달하면 `<a>` 대신 사용자 컴포넌트를 사용할 수 있다.

```tsx
import Readme from './readme.mdx';
import { FancyLink } from './components/FancyLink';

export default function Page() {
  return <Readme components={{ a: FancyLink }} />;
}
```

자주 교체하는 기본 요소는 다음과 같다.

| Markdown 표현 | 기본 요소 | 교체 예시 |
| --- | --- | --- |
| `[링크](url)` | `a` | 내부 링크 컴포넌트 |
| `![이미지](url)` | `img` | 최적화 이미지 컴포넌트 |
| `` `code` `` | `code` | 인라인 코드 컴포넌트 |
| 코드 블록 | `pre`, `code` | 복사 버튼이 있는 코드 블록 |
| `# 제목` | `h1` | 앵커가 포함된 제목 |
| `> 인용문` | `blockquote` | 경고 또는 안내 상자 |
| 표 | `table`, `thead`, `tbody`, `tr`, `th`, `td` | 반응형 표 |

기본 Markdown에서 교체할 수 있는 대표 요소는 다음과 같다.

```text
a, blockquote, br, code, em, h1, h2, h3, h4, h5, h6,
hr, img, li, ol, p, pre, strong, ul
```

`remark-gfm`을 사용하면 다음 요소도 추가로 다룰 수 있다.

```text
del, input, section, sup, table, tbody, td, th, thead, tr
```

## 15. MDX에서 JSX 컴포넌트 사용하기

컴포넌트는 HTML 태그와 구분되도록 대문자로 시작한다.

```mdx
<SeminarInfo
  title="Markdown과 MDX"
  date="2026-06-26"
  topic="문서 작성 문법"
  speakers={['Alice', 'Bob']}
/>
```

문자열 속성은 따옴표를 사용하고, 숫자·불리언·배열·객체·표현식은 중괄호를 사용한다.

```mdx
<Example
  label="문자열"
  count={3}
  enabled={true}
  tags={['markdown', 'mdx']}
  options={{ compact: true }}
/>
```

자식 내용을 받는 컴포넌트는 여는 태그와 닫는 태그를 모두 작성한다.

```mdx
<Callout>
  이 영역은 컴포넌트의 `children`으로 전달됩니다.
</Callout>
```

JSX 중괄호 안에서는 JavaScript 표현식을 사용할 수 있다.

```mdx
<p>계산 결과: {2 + 3}</p>
```

다만 문서가 데이터나 복잡한 로직에 과도하게 의존하면 일반 텍스트로서의 가독성과 유지보수성이 떨어진다. 복잡한 처리는 컴포넌트 내부로 옮기고 MDX에서는 선언적인 속성만 전달하는 편이 좋다.

## 16. 이 블로그에서 사용할 수 있는 MDX 컴포넌트

현재 블로그의 MDX 설정에는 다음과 같은 사용자 컴포넌트가 등록되어 있다.

| 컴포넌트 | 용도 |
| --- | --- |
| `CategoryPostList` | 카테고리 게시물 목록 출력 |
| `FancyShowcase` | 시각적 예제 또는 소개 카드 |
| `SeminarInfo` | 세미나 정보 표시 |
| `JavaScriptPlayground` | JavaScript 실행 예제 |
| `PythonPlayground` | Python 실행 예제 |
| `CipherPlayground` | 암호화 예제 |

예를 들어 현재 카테고리의 게시물 목록은 다음과 같이 삽입할 수 있다.

```mdx
<CategoryPostList
  title="같은 카테고리의 글"
  showDescription={true}
  limit={5}
/>
```

등록되지 않은 컴포넌트를 사용하면 빌드 또는 렌더링 오류가 발생한다. 새 컴포넌트를 추가할 때는 컴포넌트 파일을 만든 뒤 MDX 컴포넌트 매핑에도 등록해야 한다.

## 17. 수식

이 블로그는 `remark-math`와 `rehype-katex`를 사용하므로 인라인 수식과 블록 수식을 작성할 수 있다.

```md
질량과 에너지의 관계는 $E = mc^2$이다.
```

블록 수식은 `$$`로 감싼다.

```md
$$
I = \int_a^b f(x)\,dx
$$
```

렌더링 결과:

질량과 에너지의 관계는 $E = mc^2$이다.

$$
I = \int_a^b f(x)\,dx
$$

## 18. Frontmatter

게시물 맨 위의 YAML 영역은 제목, 날짜, 설명 같은 메타데이터를 정의한다.

```yaml
---
title: 'Markdown과 MDX 문법'
date: '2026-06-26'
description: 'Markdown과 MDX 문법을 정리합니다.'
titleSlide: true
manualSlides: false
---
```

frontmatter는 반드시 파일의 첫 줄에서 시작해야 한다.

| 필드 | 의미 |
| --- | --- |
| `title` | 게시물 제목 |
| `date` | 작성 또는 수정 날짜 |
| `description` | 게시물 요약 |
| `titleSlide` | 슬라이드 제목 페이지 사용 여부 |
| `manualSlides` | 수동 슬라이드 분할 사용 여부 |
| `background` | 게시물 또는 슬라이드 배경 설정 |

## 19. Markdown과 MDX 작성 원칙

문서를 안정적으로 유지하려면 다음 기준을 지키는 것이 좋다.

1. 일반 문서는 가능한 한 Markdown으로 작성한다.
2. Markdown으로 표현하기 어려운 기능만 HTML 또는 MDX 컴포넌트로 구현한다.
3. 제목 단계를 건너뛰지 않는다.
4. 코드에는 언어를 명시하고, 긴 코드에는 파일명을 붙인다.
5. 링크 텍스트는 목적지를 설명하도록 작성한다.
6. 이미지에는 의미 있는 대체 텍스트를 제공한다.
7. 복잡한 JavaScript 로직은 MDX 본문이 아니라 컴포넌트로 분리한다.
8. JSX 태그는 반드시 올바르게 닫는다.
9. `<`, `{`, `}`처럼 MDX 파서가 해석할 수 있는 문자를 일반 문장에 쓸 때는 코드 표기나 이스케이프를 사용한다.
10. 작성 후 포스트 뷰와 슬라이드 뷰를 모두 확인한다.

# 1. 문서 목적

이 문서는 현재 블로그에 구현된 기능을 코드 기준으로 정리한 기능 명세다.

- 콘텐츠 작성자가 사용할 수 있는 MD/MDX 문법
- 일반 포스트 및 슬라이드 렌더링 방식
- 슬라이드 발표, 필기, 메모 및 임시 편집 기능
- 로컬 Markdown 업로드 미리보기
- 라우팅, 테마, 인쇄 및 사용자 데이터 보존 범위
- 인터랙티브 MDX 컴포넌트와 부가 페이지

이 문서의 경로는 다음과 같다.

```txt
/Practice/Next.js/blog-feature-specification
/Practice/Next.js/blog-feature-specification/slide
```

# 2. 기술 구성

| 영역 | 사용 기술 |
|---|---|
| 애플리케이션 | Next.js App Router |
| UI | React, Tailwind CSS |
| 콘텐츠 | Markdown, MDX, gray-matter |
| MDX 렌더링 | next-mdx-remote |
| 코드 강조 | rehype-pretty-code, Shiki |
| 수식 | remark-math, rehype-katex |
| 확장 Markdown | remark-gfm |
| 정적 배포 | GitHub Pages 호환 정적 빌드 |

프로덕션 빌드에서는 포스트 경로가 정적으로 생성된다. 로컬 개발과 GitHub Pages 배포 환경의 base path 차이는 내부 경로 처리 함수가 보정한다.

# 3. 콘텐츠 파일과 URL

포스트는 `posts` 디렉터리 아래의 `.md` 또는 `.mdx` 파일로 작성한다.

```txt
posts/{category}/{slug}.mdx
→ /{category}/{slug}

posts/{category}/{slug}.mdx
→ /{category}/{slug}/slide
```

예시:

```txt
posts/Practice/Next.js/example.mdx
→ /Practice/Next.js/example
→ /Practice/Next.js/example/slide
```

특수 파일:

- 루트의 `posts/index.mdx`는 홈 콘텐츠다.
- `index.mdx`는 카테고리 대표 페이지로 사용할 수 있다.
- 빈 파일 또는 frontmatter만 있고 본문이 없는 파일은 포스트 목록에서 제외된다.

# 4. Frontmatter 명세

```yaml
---
title: '포스트 제목'
date: '2026-07-24'
description: '포스트 설명'
titleSlide: true
manualSlides: false
background:
  color:
    light: '#ffffff'
    dark: '#000000'
  image: 'background.png'
---
```

| 필드 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | string | slug | 포스트 및 제목 슬라이드 제목 |
| `date` | string | 빈 문자열 | 포스트 날짜 |
| `description` | string | 빈 문자열 | 포스트 설명 |
| `titleSlide` | boolean | `true` | 슬라이드 첫 장에 제목 슬라이드 생성 여부 |
| `manualSlides` | boolean | `false` | `---` 기반 수동 슬라이드 분할 여부 |
| `background` | string/object | 없음 | 슬라이드 배경색 또는 배경 이미지 |

`background`가 문자열이면 공통 배경색으로 처리한다. 객체의 `color`에는 공통 색상 문자열 또는 `{ light, dark }` 객체를 지정할 수 있고, `image`에는 공통 배경 이미지를 지정한다. 상대 이미지 경로는 다음 위치를 기준으로 해석한다.

```txt
public/images/{category}/{slug}/{filename}
```

# 5. 일반 포스트 뷰

일반 포스트 뷰는 다음 기능을 제공한다.

- MDX 본문 렌더링
- 제목 기반 목차와 앵커 링크
- 카테고리 탐색 사이드바
- 코드 구문 강조와 파일명 표시
- 코드 복사 버튼 및 긴 코드 접기
- 상대 이미지 경로 자동 해석
- GitHub Flavored Markdown 테이블과 취소선
- KaTeX 수식 렌더링
- 등록된 React 컴포넌트 실행
- 라이트 및 다크 색상 대응

목차의 heading ID는 렌더러와 동일한 slug 규칙을 사용한다. 같은 제목이 여러 번 나오면 `-1`, `-2` 형식의 suffix가 붙는다.

# 6. MDX 처리 파이프라인

MDX 원문에는 다음 플러그인이 순서대로 적용된다.

1. `remarkGfm`
2. `remarkToc`
3. `remarkMath`
4. `remarkNormalizeCodeMeta`
5. `remarkGridBlock`
6. `rehypeSlug`
7. `rehypeKatex`
8. `rehypePrettyCode`
9. `rehypeInjectTitle`

주요 처리 결과:

- GFM 테이블, 체크리스트, 취소선 지원
- `$...$`, `$$...$$` 수식 지원
- heading에 고유 ID 삽입
- Shiki `dark-plus` 코드 강조
- 코드블록 파일명 메타데이터 정규화
- 커스텀 그리드 블록을 React 컴포넌트로 변환

업로드한 일반 Markdown의 이메일 자동 링크 `<name@example.com>`는 MDX가 JSX로 오인하지 않도록 `mailto:` 링크로 전처리한다. 코드블록과 인라인 코드 안의 문자열은 변환하지 않는다.

# 7. 코드블록

지원하는 파일명 표기:

````md
```ts:example.ts
const value = 1;
```

```ts title="example.ts"
const value = 1;
```

```ts file="example.ts"
const value = 1;
```

```ts [example.ts]
const value = 1;
```
````

코드블록은 다음 기능을 제공한다.

- 언어별 구문 강조
- 파일명 헤더
- 클립보드 복사
- 긴 코드 접기 및 펼치기
- 슬라이드 안에서 제한된 높이와 내부 스크롤
- `js`, `ts`, `cs`, `py`, `sh`, `shell` 언어 alias

# 8. 이미지와 그리드

일반 Markdown 이미지는 포스트별 이미지 디렉터리를 기준으로 해석한다.

```md
![설명](diagram.png)
```

커스텀 그리드는 `![`와 `]!`로 감싼다.

````md
![
첫 번째 셀 | 두 번째 셀
,
***python
print('code cell')
***
]!
````

그리드 문법:

- 공백을 포함한 ` | `는 같은 행의 열을 나눈다.
- 쉼표만 있는 줄은 다음 행을 시작한다.
- 단일 셀 행은 전체 열을 차지한다.
- `***language`와 `***` 사이에는 코드 셀을 작성한다.

# 9. MDX 인터랙티브 컴포넌트

MDX에서 등록된 컴포넌트를 JSX 형식으로 사용할 수 있다.

| 컴포넌트 | 기능 |
|---|---|
| `CategoryPostList` | 현재 카테고리의 포스트 목록 |
| `CipherPlayground` | Caesar/Vigenere 암호화 실습 |
| `JavaScriptPlayground` | 브라우저 JavaScript 실행 |
| `PythonPlayground` | Pyodide 기반 Python 실행 |
| `FancyShowcase` | 탭·선택 UI 쇼케이스 |
| `SeminarInfo` | 세미나 정보 카드 |
| `GridBlock`, `GridItem` | 커스텀 그리드 레이아웃 |

Python 런타임은 최초 실행 시 브라우저에서 내려받기 때문에 첫 실행에 시간이 걸릴 수 있다.

# 10. 슬라이드 생성

## 자동 분할

기본 모드에서는 Markdown 요소의 가중치를 계산해 슬라이드를 자동 분리한다.

| 요소 | 기본 가중치 |
|---|---:|
| 일반 텍스트 | 1 |
| 코드 | 2 |
| 수식 | 1.5 |
| 이미지 | 5 |
| HTML/복합 블록 | 9 |

한 슬라이드의 목표 최대 가중치는 10이다. 코드와 이미지 같은 복합 요소는 남은 공간을 기준으로 크기가 재분배된다.

## 수동 분할

`manualSlides: true`이면 본문의 `---`를 기준으로 슬라이드를 직접 분리한다. 코드블록과 수식 블록 내부의 `---`는 구분자로 처리하지 않는다.

## 제목 슬라이드

`titleSlide`가 `true`이면 제목, 설명, 날짜 및 원문 포스트 링크를 포함한 제목 슬라이드가 첫 장에 추가된다.

# 11. 슬라이드 탐색과 표시

슬라이드 뷰는 다음 기능을 제공한다.

- 현재 슬라이드 번호와 전체 장수 표시
- 제목 계층을 보여주는 목차
- heading 단위 바로 이동
- URL hash `#slide-N` 동기화
- 마지막 슬라이드 위치를 `localStorage`에 저장
- `?reset`으로 저장된 진행 위치 초기화
- 창 크기에 맞춘 콘텐츠 자동 축소
- 전체화면 전환
- 전체화면에서 상단·하단 UI 자동 숨김
- 시스템/라이트/다크 슬라이드 테마
- 포스트 뷰로 돌아가기

## 기본 단축키

| 키 | 동작 |
|---|---|
| `←`, `→` | 이전/다음 슬라이드 |
| `Space` | 다음 슬라이드 |
| `Home`, `End` | 첫/마지막 슬라이드 |
| `J`, `K` | 이전/다음 최상위 섹션 |
| `T` | 목차 열기/닫기 |
| `F` | 전체화면 전환 |
| `P` | PDF 인쇄 |
| `D` | 그리기 모드 전환 |
| `Esc` | 목차·전체화면 종료 또는 포스트로 돌아가기 |

입력창, 메모, Markdown 편집기에서 타이핑 중일 때는 슬라이드 단축키가 실행되지 않는다.

# 12. 슬라이드 그리기

그리기 모드를 켜면 마우스와 터치 포인터로 슬라이드 위에 필기할 수 있다.

## 도구

- 자유 붓
- 부분 지우개
- 현재 슬라이드 전체 필기 삭제
- 붓과 지우개 크기 `2px`부터 `42px`
- 임의 RGB 색상 선택
- 검정, 흰색, 빨강, 파랑, 초록, 노랑 프리셋

프리셋 순서:

1. 검정
2. 흰색
3. 빨강
4. 파랑
5. 초록
6. 노랑

## 그리기 단축키

| 키 | 동작 |
|---|---|
| `1`~`4` | 검정·흰색·빨강·파랑 선택 |
| `←`, `→` | 색상 프리셋 순환 |
| `↑`, `↓` | 붓/지우개 크기를 2px씩 조절 |
| `E` | 붓과 부분 지우개 전환 |
| `C` | 현재 슬라이드 필기 전체 삭제 |

그리기 내용은 슬라이드 고유 ID별로 메모리에 보관된다. 다른 슬라이드로 이동하거나 그리기 모드를 종료해도 유지되며, 창 크기와 전체화면이 바뀌어도 보존된다.

# 13. 임시 필기 슬라이드

그리기 툴바의 `Note` 버튼은 현재 슬라이드 바로 다음에 임시 필기 슬라이드를 만든다.

- 생성 즉시 새 슬라이드로 이동
- 그리기 모드 자동 활성화
- 라이트 테마는 흰 배경
- 다크 테마는 검정 배경
- `TEMP NOTE` 배지 표시
- 임시 슬라이드에서만 `Delete` 버튼 표시
- 삭제 전 확인 후 이전 슬라이드로 이동
- 원본 MDX 및 포스트 파일에는 영향 없음

임시 슬라이드는 브라우저 메모리에서만 유지되므로 새로고침하면 사라진다.

# 14. 슬라이드 텍스트 메모

상단의 `Memo` 버튼은 현재 슬라이드에 PPT 글상자 형태의 메모를 추가한다. 그리기 모드가 아니어도 사용할 수 있다.

- 한 슬라이드에 여러 메모 생성
- 새 메모는 중앙 부근에 배치
- 상단 손잡이를 드래그하여 자유 이동
- 슬라이드 밖으로 완전히 벗어나지 않도록 이동 범위 제한
- 내용에 맞춰 너비와 높이 자동 조절
- 최대 높이 초과 시 내부 스크롤
- 메모별 독립 편집 및 삭제
- 슬라이드 이동 시 자동 포커스하지 않음
- 라이트/다크 테마 대응
- 슬라이드별 메모 내용과 위치 유지

메모도 클라이언트 메모리에서만 유지되며 원본 파일을 수정하지 않는다.

# 15. 클라이언트 Markdown 수정 모드

상단의 `Edit` 버튼을 누르면 현재 슬라이드의 Markdown 원문을 편집할 수 있다.

1. `Edit`을 눌러 원문 편집기를 연다.
2. Markdown 또는 MDX를 임시 수정한다.
3. `Render`를 눌러 클라이언트에서 다시 컴파일한다.
4. 성공하면 수정된 슬라이드가 렌더링된다.
5. 실패하면 편집기를 유지하고 컴파일 오류를 표시한다.

수정 결과는 현재 브라우저 세션의 React 상태에만 저장된다.

- 원본 `.md`/`.mdx` 파일을 수정하지 않는다.
- 서버 파일 시스템에 쓰지 않는다.
- 새로고침하면 임시 수정 내용이 사라진다.
- 수정된 렌더링은 PDF 출력에도 반영된다.
- 클라이언트 안전 MDX 컴포넌트만 편집 미리보기에 사용한다.

# 16. PDF 및 인쇄

`P` 키 또는 프린트 버튼으로 전체 슬라이드를 가로 방향 PDF로 출력할 수 있다. 브라우저의 `Ctrl+P`도 지원한다.

인쇄 결과에는 다음 항목이 포함된다.

- 원본 슬라이드 콘텐츠
- 클라이언트에서 임시 수정한 Markdown 렌더링
- 슬라이드별 캔버스 필기
- 임시 필기 슬라이드
- 모든 텍스트 메모
- 메모의 이동 위치와 줄바꿈
- 선택한 라이트/다크 테마 및 배경

인쇄 직전에 각 슬라이드의 캔버스를 PNG 이미지로 캡처해 해당 인쇄 슬라이드 위에 겹쳐 출력한다.

# 17. 로컬 Markdown 업로드

`/upload`에서는 로컬 `.md` 또는 `.mdx` 파일을 선택해 서버 저장 없이 미리 볼 수 있다.

- 파일 선택 및 드래그 앤 드롭
- 최대 원문 크기 500,000자
- frontmatter 간이 파싱
- 일반 포스트 미리보기
- 슬라이드 미리보기
- 자동/수동 슬라이드 분할
- 같은 MDX 플러그인 스택 적용
- 이미지 파일을 함께 올려 상대 경로 미리보기
- 컴파일 오류 표시

업로드한 파일과 이미지는 브라우저에서만 처리된다. 이미지 Object URL은 컴포넌트 종료 시 해제된다.

# 18. 테마와 배경

슬라이드 테마는 다음 세 상태를 순환한다.

```txt
System → Dark → Light → System
```

선택값은 포스트 경로별로 `localStorage`에 저장된다. 시스템 모드는 운영체제의 `prefers-color-scheme` 설정을 따른다.

커스텀 배경이 있으면 라이트·다크 테마별 색상과 공통 배경 이미지를 사용할 수 있다. 임시 필기 슬라이드는 커스텀 배경 대신 흰색 또는 검정색 필기판을 사용한다.

# 19. 부가 페이지

## 홈

`/`는 `posts/index.mdx`를 렌더링하며 주요 카테고리와 문서 링크를 제공한다.

## 소개

`/about`은 소개 콘텐츠를 표시한다.

## 업로드

`/upload`는 로컬 MD/MDX 미리보기 도구다.

## 게임

`/game`에는 브라우저 게임이 포함된다.

- 지뢰찾기
- 숫자 야구
- 캔버스 기반 공룡 달리기
- 공룡 게임 최고 점수 `localStorage` 저장
- 키보드 입력 지원

# 21. 안전 및 제약사항

- 슬라이드 편집 기능은 클라이언트 미리보기이며 원본 파일 저장 기능이 아니다.
- 임시 데이터는 페이지를 새로고침하거나 슬라이드뷰를 완전히 종료하면 사라질 수 있다.
- MDX 컴파일에서는 위험한 JavaScript 실행을 차단한다.
- 업로드 원문에는 크기 제한이 있다.
- 브라우저의 PDF 옵션에서 배경 그래픽을 허용해야 배경색과 이미지가 가장 정확하게 출력된다.
- Python Playground 최초 실행은 외부 런타임 로딩이 필요하다.

# 22. 기능 확인 체크리스트

- 일반 포스트와 `/slide` 경로가 모두 열린다.
- 목차와 heading 앵커가 일치한다.
- 코드 파일명, 강조, 복사 및 접기가 동작한다.
- GFM 테이블과 KaTeX 수식이 렌더링된다.
- 자동 및 수동 슬라이드 분할이 동작한다.
- 슬라이드 위치와 테마가 새로고침 후 복원된다.
- 색상, 굵기, 붓, 부분 지우개가 동작한다.
- 슬라이드별 필기가 서로 섞이지 않는다.
- 임시 필기 슬라이드 생성 직후 해당 슬라이드로 이동한다.
- 임시 슬라이드 삭제 후 이전 슬라이드로 돌아간다.
- 한 슬라이드에 여러 텍스트 메모를 만들고 이동할 수 있다.
- 슬라이드 이동 시 메모 입력창에 자동 포커스하지 않는다.
- Markdown 임시 수정 후 `Render`로 다시 렌더링된다.
- 원본 포스트 파일은 변경되지 않는다.
- PDF에 필기, 임시 슬라이드, 메모, 임시 Markdown 수정이 포함된다.
- `/upload`에서 MD/MDX 포스트와 슬라이드를 미리 볼 수 있다.

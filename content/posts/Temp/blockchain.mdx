    3. 소유권 확인
- 비트코인 저장 방식: Desktop, Mobile, Web, **Hardware**

## Pay to Public Key (P2PK)
- a가 b에게 코인을 지불할 때, b의 공개 키를 사용해서 트랜잭션을 올림
- b의 사인 - b의 공개키 - checksig의 형태로 스택이 쌓임. 스택 쌓으면서 op처리
- 문제점:  공개키를 얻기 위해 IP가 공개됨, 미들웨어 어택이 가능함. 
- 공개키가 대놓고 공개됨 -> 나중에 양자컴퓨터에 의한 보안 위험성 -> 최근엔 Hash 덧붙여 사용함
- 주소를 지정해야 함 -> 오타 문제 

## P2PKH
- 수신자 b가 a에게 자신의 주소(해시)를 주고 a가 해당 해시가 담긴 output script를 날림
- b가 자신의 서명과 공개키를 가지고 해당 코인을 받아옴.  
- Input에서의 공개키가 해시 값과 비슷한지 확인 후, 서명 확인 절차를 걸침.

# 블록체인 및 비트코인 핵심 기술 심화 정리

## 1. 블록체인의 가치와 신뢰 구조
### 디지털 데이터의 한계 극복: 탈중앙화
- **이중 지불(Double Spending)**: 디지털 자산의 무한 복제 가능성을 해결하기 위해 기존의 '중앙 서버(은행)' 대신 '탈중앙화된 P2P 장부'를 도입함.
- **불변성(Immutability)**: 해시(Hash) 함수로 연결된 블록 구조를 통해 과거 데이터를 수정하려면 이후의 모든 블록을 다시 채굴해야 하므로 사실상 수정이 불가능함.
- **수학적 신뢰**: 사람이 아닌 알고리즘(PoW)과 암호학(ECC)에 기반하여 신뢰를 구축함.

---

## 2. 암호학적 기초: 키 생성과 타원곡선 (ECC)
### 개인키 (Private Key)
- **생성**: CSPRNG(암호학적으로 안전한 난수 생성기)와 SHA-256 해싱을 결합하여 생성함.
- **규모**: 약 $2^{256}$($10^{77}$)개의 경우의 수를 가지며, 이는 관측 가능한 우주의 원자 수($10^{80}$)에 육박하는 수준으로 무작위 생성 시 중복 가능성이 사실상 없음.

### 타원곡선 암호화 (secp256k1)
- **수식**: $y^2 = x^3 + 7 \pmod p$
- **공개키 생성**: 개인키($k$)와 타원곡선상의 기준점($G$)을 곱하여 공개키($K$)를 도출함 ($K = k \times G$).
- **비가역성**: 타원곡선상의 점의 덧셈과 스칼라 곱셈은 계산이 쉽지만, 결과값($K$)과 $G$를 보고 원래의 $k$를 알아내는 것은 현대 컴퓨팅 기술로 불가능함(이산 로그 문제).

---

## 3. 비트코인 주소 체계의 진화 (P2PK ~ Taproot)
비트코인은 소유권을 증명하기 위해 **Locking Script(출력)**와 **Unlocking Script(입력)** 구조를 사용합니다.

### 1세대: P2PK (Pay-to-Public-Key)
- **특징**: 초기 비트코인(v0.1)에서 사용된 방식으로, 공개키를 직접 Locking Script에 포함함.
- **방식**: IP 주소를 통해 직접 송금하거나 노드 간 통신으로 공개키를 획득함.
- **문제점**: 
    - **보안**: 공개키가 네트워크상에 노출되어 양자 컴퓨터 등의 공격에 취약할 수 있음.
    - **프라이버시**: IP 추적 및 중간자 공격(Man-in-the-middle) 위험이 있음.
    - **크기**: 65바이트의 비압축 공개키를 그대로 사용하여 블록 공간을 많이 차지함.

### 2세대: P2PKH (Pay-to-Public-Key-Hash)
- **혁신**: 공개키 자체가 아닌 **공개키의 해시값**을 주소로 사용함. '1'로 시작하는 주소.
- **기술적 과정 (HASH160)**: `RIPEMD160(SHA256(Public Key))`
    - 65바이트의 공개키를 20바이트의 해시값으로 압축하여 효율성 증대.
    - 거래가 실제로 일어나기 전까지는 원본 공개키가 노출되지 않아 보안성 강화.
- **Base58Check 인코딩**:
    - 읽기 쉬운 형식으로 변환하며 0, O, I, l 등 헷갈리기 쉬운 문자를 제외함.
    - 주소 끝에 4바이트의 체크섬을 추가하여 오타로 인한 오송금 방지.

### 3세대: P2SH (Pay-to-Script-Hash)
- **특징**: 복잡한 조건(예: 3명 중 2명의 서명이 필요한 다중 서명)의 스크립트 해시를 주소로 사용함. '3'으로 시작하는 주소.
- **장점**: 송금자는 복잡한 조건을 알 필요 없이 해시값으로만 송금 가능하며, 데이터 전송 비용을 수신자가 지불하게 함.

### 4세대: SegWit (Bech32) & Taproot (Bech32m)
- **Bech32 (P2WPKH)**: 'bc1'로 시작함. 대소문자 구분을 없애고 오류 검출 능력을 극대화함.
- **특징**: '서명(Witness)' 데이터를 트랜잭션 본문에서 분리하여 블록 용량 문제를 해결하고, 거래 가변성(Malleability) 문제를 수정함.
- **Taproot**: 복잡한 스마트 컨트랙트를 일반 거래처럼 보이게 하여 프라이버시를 더욱 강화함.

## 4. 트랜잭션 운영 모델: UTXO
비트코인은 계좌 잔고 방식이 아닌 **미사용 출력값(UTXO)** 모델을 따릅니다.

- **원자성**: 하나의 UTXO는 쪼개서 쓸 수 없으며, 전체를 소모한 뒤 남은 금액을 '잔돈(Change)' 주소로 새로 생성함.
- **입출력 구조**:
    - **Inputs**: 이전 거래의 UTXO를 가리키며, 개인키 서명을 통해 소유권을 증명(Unlocking).
    - **Outputs**: 새로운 소유자의 주소(해시)와 잠금 조건(Locking)을 설정함.
- **수수료**: `Total Inputs - Total Outputs`의 차액이 채굴자의 보상이 됨.

---

## 5. 핵심 최적화 기술
- **압축된 공개키 (Compressed Public Keys)**: 타원곡선은 x축 대칭이므로 x좌표와 y의 부호(홀/짝)만 저장하여 크기를 33바이트로 줄임.
- **WIF (Wallet Import Format)**: 개인키를 안전하게 백업하고 다른 지갑으로 옮기기 위해 Base58Check를 적용한 포맷.
- **Vanity Address**: '1Love...'와 같이 특정 문구로 시작하는 주소를 만들기 위해 무차별 대입(Brute-force) 방식으로 생성한 주소.

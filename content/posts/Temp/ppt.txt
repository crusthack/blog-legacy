# 1. 취약점 소개
- CVE 번호: CVE-2026-25778
- CVSS 점수: 7.3(위험도 높음)
- 취약점에 영향 받는 제품: **Swtchenergy**사의 **전기차 충전소** 및 충전소 백엔드 망 
- 취약 항목: 세션 연결에 있어서 불완전한 식별 및 인증 매커니즘의 부재 
- 취약점 분류: CWE-613 (부적절한 세션 관리 (Insufficient Session Expiration))
- 발견자: Khaled Sarieddine and Mohammad Ali

## 취약점 세부 내용
- 각 전기차 충전소는 백엔드로 웹소켓 통신을 활용해 중앙 서버와 통신 
- 서버측에서 각 충전소를 식별하는 과정에서 사용하는 식별값으로 예측 가능한 규칙적인 값이 사용됨
- 충전소별 식별값 외의 내부적인 인증 시스템이 존재하지 않음.  <br/><br/>
=> 인증 시스템의 부재. 예측 가능한 식별값을 가지고만 세션 연결이 수립됨.  <br/><br/>
- 특정 세션에 대한 새로운 연결이 들어올 시, 검증 없이 기존 연결을 끊고서 새로운 연결을 수립  <br/><br/>
=> **기존의 정상적인 연결이 끊어지고 악의적인 행위자와의 연결이 정상적으로 취급되게 됨**

## 잠재적 위험성 
- 세션 섀도잉: 기존 세션을 밀어냄으로써 정상적인 서비스 사용을 방해 
- 세션 하이재킹: 정당한 세션연결을 낚아챔으로써 정상 세션이라고 위장
##### 발생할 수 있는 문제
- 인프라 마비 - 가용성 공격
- 데이터 유출
- 과금 문제
- ...

## 정상적인 충전소 동작 시나리오 
1. 충전소 전원 켜짐. 서버에 자신의 식별값 (예. \{STATION_001}) 접속,  
서버측에서 세션 연결 수립 (\{STATION_001}과의 세션 연결)
2. 사용자는 충전소의 기기를 조작하여 결제 및 전기차 충전기 연결, 충전 시작 
3. 충분한 충전이 완료된 후 사용자가 직접 충전 종료 요청, 혹은 충전 가능 시간이 끝나면 서버측에서 충전 종료 명령 

## 세션이 탈취됐을 시 위험성 
1. 충전소 전원 켜짐. 서버에 자신의 식별값 (예. \{STATION_001}) 접속,  
서버측에서 세션 연결 수립 (\{STATION_001}과의 세션 연결)  
**서버와의 세션 연결이 지속적으로 끊겨서 정상적인 통신이 불가능**
2. 사용자는 충전소의 기기를 조작하여 결제 및 전기차 충전기 연결, 충전 시작   
**사용자 요청이 서버에 도달하지 못 하거나, 잘못된(조작된) 요청으로 변조 가능. 혹은 데이터 탈취 위험**
3. 충분한 충전이 완료된 후 사용자가 직접 충전 종료 요청, 혹은 충전 가능 시간이 끝나면 서버측에서 충전 종료 명령   
**종료 요청이 도달하지 않아 지속적인 결제 발생, 혹은 결제량을 넘어선 충전이 발생 가능**
##### 세션 탈취로 인한 여러가지 서비스 장애가 발생 가능 
- 충전소 사칭, 세션 하이재킹, 서비스 거부(DoS), 데이터 조작...등 

# 2. 코드상의 문제 
- 직접적인 코드는 공개되어 있지 않아, 취약점 내용을 토대로 코드를 예측하여 설명 
## 식별값 기반 세션 연결 요청 
```js
import websocket

target_id = "STATION_001" # 규칙성을 찾을 수 있는, 예측가능한 식별값 
malicious_url = f"wss://backend.swtch.com/ocpp/{target_id}"

# 별도의 인증 과정 없이 URL만으로 접속 시도
ws = websocket.create_connection(malicious_url)
```

## 서버측에서 연결 요청받았을 때, 기존 세션 덮어 씌우기 
```js 
// 연결 들어왔을 때 발생하는 이벤트 
server.on('connection', (newSocket, req) => {
    const stationId = extractIdFromUrl(req.url); // 세션값 파싱 
    // [핵심 결함 지점] 중복 세션에 대한 검증 없는 덮어쓰기
    if (sessionMap.has(stationId)) {
        console.log(`중복 접속 감지: ${stationId}. 기존 세션을 제거합니다.`);
        // 기존의 충전소 연결을 강제로 종료(Displace)
        const oldSocket = sessionMap.get(stationId);
        oldSocket.terminate(); 
    }
    // 새로운 연결(공격자)을 유효 세션으로 등록
    sessionMap.set(stationId, newSocket);
});
```

## 문제점 정리 
1. 예측가능한 식별 ID를 통한 충전소 식별 
2. 부적절한 인증 시스템. 단순 식별ID만을 가지고 인증 수행(제대로된 인증 절차의 부재)
3. 새로운 세션 연결 요청시 기존 세션 덮어쓰기(기존 세션에 대한 처리 부족)  
=> 왜 이렇게 구현했을까? 
- 인증 처리 구현하기 귀찮음. 
- 네트워크 환경 고려한 복잡한 세션 처리 대신 그냥 기존 세션을 덮어써버리면 서비스 구현이 단순해짐  
(예, 네트워크 상의 문제로 연결이 끊겼다가 다시 연결할 때 처리)

# 3. 취약점 보완 방안 및 애플리케이션 개발시 유의사항 

## 인증 시스템(mTLS) 도입 
- 기존 고정적인/예측가능한 식별값 사용 대신, 비대칭키 인증 시스템 혹은 예측 불가능한 토큰 값 사용 
- 혹은, 하드웨어에 내장된 인증서를 확인해 상호 인증 처리를 하는 mTLS 도입 

## 세션 관리    
- 이미 연결된 충전소에 대해서 중복된 연결 요청이 들어올 시, 기존의 연결에 대해 생존 여부 확인. 혹은 단순 새로운 연결 차단 
- 새로운 세션 수립할 시 기존 컨텍스트, 상태 초기화
- 세션에 고유 값을 부여해 독립적으로 처리 

## etc 
- 중복 접속 차단 및 고유 식별자 강제:  
연결당 유일한 세션 식별자를 부여하고, 동일 ID로 동시에 여러 곳에서 접속하는 것을 방지하여 세션 섀도잉을 원천 차단

- 예측 불가능한 세션 토큰 도입:  
장비 S/N 같은 예측 가능한 값 대신, 암호학적으로 안전하고 무작위적인 세션 토큰(CSPRNG 기반)을 사용하여 식별자 예측 공격 방지

- 강력한 세션 만료 메커니즘:  
사용되지 않거나 오래된(Stale) 세션이 재사용되거나 하이재킹되지 않도록, 서버 측에서 엄격한 세션 만료 및 폐기(Invalidation) 구현

- 백엔드 검증 강화:  
모든 세션 요청의 정당성을 백엔드에서 엄격히 검증하고, 중복되거나 의심스러운 연결 시도는 거부  
...

- 네트워크 노출 제한:  
백엔드 시스템을 인터넷에 직접 노출하지 않고, 신뢰할 수 있는 네트워크 내부로 제한하거나 VPN 및 강력한 상호 인증(mTLS)을 거쳐야만 접속 가능하도록 설정

- 속도 제한(Rate Limiting) 및 이상 탐지:  
웹소켓 백엔드에 요청 속도 제한을 적용하여, 서비스 거부(DoS) 공격으로 이어질 수 있는 대량의 세션 플러딩(Flooding) 시도를 차단

- 실시간 모니터링 및 로깅:  
비정상적인 세션 활동이나 반복적인 세션 밀어내기(Displacement) 이벤트를 감지하기 위해 로그를 상시 모니터링

- 공식 패치 적용:  
SWITCH EV 제조사와 지속적으로 소통하여 본 취약점을 해결하는 공식 보안 패치가 출시되는 즉시 시스템에 적용

- 보안 평가 및 교육:  
정기적인 침투 테스트(Penetration Testing)를 통해 세션 관리 제어를 점검하고, 운영팀에게 세션 하이재킹의 위험성과 안전한 세션 처리의 중요성을 교육

## 정리 
- 떨어진 두 노드간의 통신에 대해 암호화 및 인증 처리를 적절한 수준으로 수해하여야 함.
- 중복된 세션 연결에 대한 처리를 구상해야함. 가장 쉬운건, 이미 연결된 세션에 대해 새로운 연결을 거부(1차적 해결방안)  
혹은, 여러가지 조건을 따져봤을 때 기존 연결을 버리고 새로운 연결을 선택하는 것 또한 능동적으로 수행

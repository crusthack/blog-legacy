# 고전 암호(아날로그)
### 단일문자 암호(monoalphabetic cipher)
#### 덧셈 암호(shift cipher)
- 평문 전체를 하나의 키값에 따라 각 문자를 이동시키는 암호. 줄리우스 시저가 이 암호를 사용했다고 유명함.
- 해독시에는 암호화시에 한 연산의 역산을 수행해야 함. 덧셈을 했으면 뺄셈, 혹은 그 역.
- 기존 알파벳만을 생각한다면 키값이 25개(26개에서 키값이 0인 경우 제외)밖에 존재하지 않음으로 쉽게 해독이 가능.

#### 곱셈 암호(multiplicative cipher)
- 평문의 각 문자에 곱셈을 수행함으로써 암호화하는 방식. 
- 해독시에는 키값을 나누는게 아닌, 키의 곰셈에 대한 역원을 곱하는 방식으로 해독을 수행함
- (p * k * k^-1) mod 26 = p. 26의 곰섹 역원 쌍이 6개밖에 없으므로 키가 될 수 있는건 12개뿐임

#### 아핀 암호(affine cipher)
- 2개의 키를 사용해 덧셈과 곱셈 연산을 복합적으로 사용하는 방식.

#### 단일 문장 암호의 한계
- 각 문자에 대해 개별적인 연산이 들어감으로 각 문자별로 대응되는 암호 문자가 정해지게 됨.
- 경우의 수는 26!으로, 적지 않은 경우지만 문자의 출현 빈도수에 대한 예측이 가능하기에
(e.g. 영문은 대체로 e, t, a...와 같은 문자들이 자주 사용됨) 통계적인 공격이 쉬움.

### 다중 문자 암호(polyalphabetic substitution)

#### 자동키 암호(autokey cipher)
- 첫 번째 문자를 사전에 정해둔 암호키로 암호화한 뒤, 뒤의 n+1번째 문자는 n번째 문자를 키값으로 이용해 암호화
- 특정 문자에 대한 빈도수 문제 해결이 가능하지만 아직 암호자체가 너무 단순함. 

#### 플레이페어 암호(playfair cipher)
- 5*5 격자판에 문자들을 배치하고(i와 j는 같은 칸에 배치) 특정 규칙에 따라 평문의 연속된 문자 쌍을 이용해 암호화 수행.
- 문자 쌍은 서로 달라야 함. 연속된 문자가 겹칠 때, 예를 들어 hello라는 문자를 암호화할 때는 he, ll, o를 이용해 암호화야하는데 
ll이 겹치므로 he, lx, lo 이런 식으로 중간에 더미 문자를 삽입.
- 전체 문장의 문자 수가 홀수일 때, e.g. money일 때 뒤에 더미 문자를 삽입할 수 있음. 보통 잘 쓰이지 않는 Q나 X를 삽입.
- 복호화 후 보이는 더미들은 읽을 때 문맥에 맞춰 배제해버림.
- 암호화 규칙
1. 두 문자가 격자의 같은 행에 속한다면 격자에서 각 문자의 우측에 있는 문자로 치환
2. 두 문자가 격자의 같은 열에 속한다면 격자에서 각 문자의 하단에 있는 문자로 치환
3. 두 문자가 같은 행, 열에 속하지 않는다면 각 문자는 자신의 행에서 다른 문자의 열에 대응되는 문자로 치환

#### vigenere 암호
- 키 단어를 사용해 주기적으로 덧셈 연산을 다르게 하는 키 길이가 n인 덧셈 암호
- 통계적인 분석을 통해 반복되는 부분을 찾고서 단어 유추를 할 수 있음.

#### Rotor 암호를
- 기계적인 배선(키 설정)을 통해 Input -> Output으로 문자가 치환됨. 
- 매번 입력시마다 기계가 규칙적으로 돌아가기에 문자 빈도가 보존되지 않음.

#### 에니그마
- 로터 기계 장치를 복합적으로 엮어 만들어낸 암호 기계
- 초기 설정값에 따라 Input, Output이 대칭적으로 출력됨, 즉 A 입력시 K가 나왔다면 K 입력시 A가 나오고 그에따른 로터 회전 또한 동일함. 
암호화, 복호화 과정이 동일

# 개요
- 작성한 포스트를 볼 때 가독성이 떨어진다는 느낌을 받았음. h태그 위에 패딩을 추가해봤지만 그래도 아쉬움이 있어서, 
슬라이드 형식으로 문맥을 나누어 본다면 포스트로 볼 때도 가독성좋게 작성할 수 있을 것 같아 미뤄뒀던 기능 추가를 하기로 결심하게 됨.

## AI 활용
- 웹개발은 대부분 AI를 활용 하였기 때문에, 이번에도 vs code 내장 코파일럿 에이전트를 사용해 초반 구현을 시작하였음
- 하지만 토큰이 너무 빨리 떨어지고 여러모로 아쉬운점이 많았기에 gemini CLI을 다운 받아 사용해보기로함. 
- gemini cli을 사용해서 단계적으로 기능 개발을 하였으며, 사실 세부적인 수치(폰트 크기, 컴포넌트 사이즈) 같은 걸 제외하고는 다 cli에 명령만 내려서 구현했기에 정리할 내용이 없음.
- AI 사용중 거슬렸던 내용이나 말이 잘 안 통했던 내용 정리 및 코드리뷰만 하기로 함. 

# 구현 
## 요구사항
- 기존 포스트 형식에서 내용을 그대로 사용해 문맥별로 나눠서 포스트 - 슬라이드 2가지 형식이 모두 유효했으면 좋겠음
- 주소창에 /slide만 붙이면 바로 슬라이드가 보여야 됨.
- 링크 기반으로 슬라이드 페이지가 나뉘면 안 됨. 브라우저 히스토리가 쉽게 더러워지고 뒤로가기가 힘들어진다는 단점을 느낀 경험이 있음.

## AI 사용 경험
- 맨 처음 VS code의 코파일럿에게 부탁을 하니 바로 슬라이드 페이지를 만들어 주었음. 프로젝트 전체 파악하라고 명령하니 토큰 빨리 소비해버려서, 이후 바로 gemini cli로 교체함
- gemini가 만들어주는 페이지를 확인하면서, 내용 분할을 어떻게 해야할지 생각하고 지속적으로 수정안을 내주었음. 
- 일부 경우를 제외하고는 대부분 수정을 빠르게 잘 해주었고, 모호하다고 느낄 만한 부분이 있음에도 알아서 잘 생성해 주었음. 

### 아쉬운 점 
- 세부적으로 직접 변경한 코드 부분에 대해 제미나이가 자기 스스로 복구를 하여서 이런 부분은 좀 거슬렸음.  
수치나 코드 한 두줄 수정하는 데에 대화형으로 명령하기도 귀찮은 부분이라 생각해서 아쉬웠음.
- mdx내용에 줄별로 가중치를 부여하여 슬라이드당 최대 n줄만 뜨도록 하였는데, 코드블럭이나 이미지가 있을 때에 대한 처리가 계속 미흡하였음. 
시각적인 내용에 대한 명령은 좀 더 세부적이면서도 직접적으로 해야할 것 같음. 
- j키와 k키를 이용해 h1태그 단위로 이동하는 기능을 구현하고자 하였는데, k를 누르면 **앞으로**, j를 누르면 **뒤로** 가게 해달라고 하였는데,  
k를 누르면 앞 부분으로, j를 누르면 뒷 부분으로 가도록 구현을 해주었고, 지속적으로 둘의 기능을 서로 바꾸라고 명령했는데도 계속 유지했음.  
아마 **다음** h1태그, **이전** h1태그 이런 식으로 표현해야 했을 것 같음.

# 슬라이드 생성 방식
- 슬라이드 보기 버튼이나 url 생성 부분은 건너뛰고, mdx파일을 어떻게 슬라이드로 나눴는지에 대해서만 정리합니다.
- mdx파일 전체를 `lib/slides.ts`의 `splitContentIntoSlides`에 넘겨 구간별로(h태그 단위) 나눈 뒤 파싱을 시작합니다.
1. mdx 파일 단위별로 파싱(h태그, p태그, 라인, 코드블럭, 이미지, table...)
2. h태그 단위로 섹션을 나누어 정리 
3. 섹션간의 가중치 판단 후, 같은 슬라이드에 배치하거나 슬라이드 분리 
- 이후 각 슬라이드별로 mdxremote에 넣어서 각 html생성 후 슬라이드를 화면에 띄웁니다. 

# 마무리
- AI가 생각보다 더 코딩을 잘 해줌. 감흥이 없어서 정리할게 없음. 
- 슬라이드 형식 도입으로 포스트 보기가 편해진 것 같음.

# CLR 개요
- CLR via C# 책의 각 장을 읽으면서 생각한 주요한 개념들을 간단하게 정리했습니다. 
- CLR은 C#으로 작성한 프로그램이 돌아가는 실행 환경입니다. C#은 컴파일러에 의해 IL(Intermediate Language)로 번역된 후, CLR(Common Language Runtime)위에서 JIT(Just-In-time)컴파일러와 함께
네이티브 언어로 컴파일되어 실행됩니다. 
- CLR은 중간언어 IL을 실행하는 가상 환경으로써 하드웨어, 운영체제 종속성으로부터 벗어나도록 도와줍니다.
- C#을 이용해 더 좋은 프로그램을 작성하는 법을 배우기 위해 그 실행환경인 .Net CLR 동작을 학습합니다.

# 1부 CLR 기본

## 1장 CLR의 실행 모델
- c# 소스 코드는 C# 컴파일러에 의해 매니페스트를 포함하는, IL과 메타데이터로 이루어진 관리모듈을 생성합니다. 이 결과물을 통틀어 어셈블리라고 합니다.
- JIT는 메타데이터를 통해 다음에 실행항 IL 코드(함수, 타입 단위)를 알고있습니다. JIT는 해당 코드를 실행중에 네이티브 코드로 컴파일한 뒤 해당 코드를 실행합니다.  
실행중에 한 번 컴파일된 코드는 계속 메모리에 남아 다음 호출시엔 컴파일 없이 바로 실행 가능합니다.

### 공용 언어 사양(CLS)
- CLR은 IL로 컴파일되는 여러 언어(C#, F#, Visual Basic...)들을 실행할 수 있는 가상 환경입니다. 서로 다른 언어끼리 라이브러리를 공유하기 위한 공용 언어 사양을이 정의돼있습니다.
- .Net에서의 모든 언어는 CLS을 지키며 다른 언어와의 호환을 위해서는 CLS의 기능만을 준수하여 프로그램을 작성하여야 합니다. 
- C#으로만 개발한다면 안 지켜도 됩니다. C#이 제공하는 기능 온전히 사용하면 됩니다. 

### Unmanaged 언어와의 상호 운용성
- 비관리 언어(수동 메모리 조작)와의 호환이 가능합니다.

# 2부 타입 설계

## 4장 타입 기초
- 모든 타입은 System.Object를 상속 받음. 이것은 기본 값 타입 int, float...들도 마찬가지임
- 모든 레퍼런스 객체는 **타입 객체 포인터**와 **동기화 블록 인덱스**를 가지고 있음. 
- 타입 또한 객체로서 메모리에 존재함. 
- 객체는 자신의 타입 정보를 **타입 객체 포인터**로 가리키고 있으며, 이는 동적 캐스팅을 하고 난 이후에도 동일함. 
- **타입 객체**의 **타입 객체 포인터**는 **System.Type**를 가리키고 있음. 
- 네임스페이스, 맨 위에 using문으로 네임스페이스를 사용 선언하면 컴파일 중에 해당 네임스페이스들을 밑의 객체들에 대입하면서 레퍼런스 탐색을 함.

## 5장 기본, 참조, 갑 타입
- System.Int32와 int, String과 string. 전자는 객체 타입명, 후자는 키워드. 언어 스펙은 키워드를, 저자는 타입명을 사용하는 것이 옳다고 생각.
- int보다 작은 자료형 연산시 int로 자동 승격, 이후 명시적 다운캐스팅. 
- `checked`, `unchecked` 키워드로 오버플로우 검사 가능
- string과 String은 같음. 
- 값 타입은 new로 초기화해도 스택메모리에 할당됨. new 없이 선언하면 쓰레기값, new로 초기화하면 0으로 초기화
- 값 타입은 필요에 따라 참조타입으로 박싱될 수 있음. object 파라미터에 넣거나(format(object)) GetType, Clone과 같은 Object의 비가상 메서드 호출 시, 인터페이스 캐스팅 시.
- 박싱 언박싱으로 인한 객체 참조 문제가 복잡하므로 값타입은 웬만해선 readonly로 작성.
- 객체의 동일성에 대하여... Equals 메서드 구현
- Equals 메서드 재정의 시, HashCode 메서드도 재정의 해야 함. 
- **dynamic** 타입에 대하여

## 8장 메서드
- 값 타입은 매개변수가 없는 생성자를 허용하지 않음(CLR은 허용함, C# 컴파일러는 비허용). 컴파일 에러
- 참조 타입은 생성사 미구현 시, 자동으로 기본 생성자 생성됨. 인라인 초기화 -> 생성자 호출
- 참조 타입의 필드에 있는 값 멤버는 생성자 미호출 시, 값 멤버의 필드가 0으로 초기화 됨.
- 타입 생성자 - 타입 객체가 메모리에 처음 로드될 때 호출됨. 참조타입에서만 사용
- 변환 연산자 구현. implicit, explicit을 통한 암묵, 명시적 캐스팅 정의. 
- 확장 메서드
- 부분 메서드

## 9장 매개변수

## 10장 속성(Property)
- 게터 세터 프로퍼티를 사용하면 속성 설정이 간편해짐. 컴파일러가 자동으로 게터 세터 메서드로 생성한 후 연결해줌.

- 익명 타입, 튜플 타입을 이니셜라이저 리스트를 통해 선언 가능. 불변 객체임. 
- 매개 변수 있는 속성, 인덱서를 통해 임의의 위치 접근 가능.

## 14장 문자열
- .Net에서의 char은 2바이트 자료형. UTF-16. String은 CLR이 자체적으로 지원하는 타입.
- Char은 Int32로 바로 캐스팅 가능. 제일 효율적. 혹은 Convert, IConvertible 사용
- @"payload"를 사용하면, payload 안의 이스케이프 문자가 바로 역슬래시로 취급됨.
- String은 변경되지 않음. 새로운 문자열 생성시(+연산 또한) 매번 새로 힙에 생성됨. 
- **문자열 인터닝** clr은 내부적으로 해시테이블을 사용하여 컴파일 타임에 string literal들을 관리함. 이를 문자열 인터닝이라고 함. 컴파일 타임에만 인터닝을 함. 
- CLR 버전에 따라 인터닝 동작이 수시로 변경될 수 있음. Intern에 의존적인 코드를 작성하면 안 됨.
- 인터닝 된 문자열은 해시테이블이 지속적으로 참조하고 있기에 GC에 의해 정리되지 않음. 
- **StringBuilder** 문자 배열을 직접적으로 사용해 동적으로 문자열을 관리하여 조금 더 효율적인 문자열 관리가 가능함. 
- 여러 문화권 특성에 따른 문자열 옵션과 인코딩에 대한 내용이 있는데 이는 정리하지 않음.

## 21장 가비지 컬렉터
- 0세대 gc가 가득 찬 경우 쓰레기 수집 실행
- 프로세스내의 모든 스레드가 일시 정지되고 marking phase에 돌입, 모든 객체를 순회하면서 싱크 블록 인덱스의 특정 비트를 0으로 세팅
- 활성 루트(reachable)를 돌면서 각 루트가 참조중인 객체의 특정 비트를 다시 1로 세팅
- 이후, 모든 marked 객체들을 힙의 앞으로 당김 -> 서로 연속적이게 되고 워킹 셋이 감소해 성능 향상이 있음.
- 힙 포인터를 객체들 맨 뒤로 당기면서 다시 그 뒤부터 할당 동작함.
- 가비지 컬렉터는 총 3개 세대 존재, 0세대 1세대 2세대
- 0세대 객체들이 한 번 컬레터로부터 살아남으면 1세대가 되고, 또 살아남으면 2세대가 됨
- 보통 0세대만 검사하다가 1세대 많아지면 1세대도 검사, 2세대도 검사.
- 2세대 1세대 객체의 필드중 참조가 변한 경우 카드테이블 비트 활용하여 확인
- 대형 객체 (보통 85'000 바이트 이상)는 생성 즉시 2세대로 설정
